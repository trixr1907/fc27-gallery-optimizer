# AUDIT.md — open assumptions and verification items

Living list of things the app *assumes* about FC 27 / FUT.GG that are **not**
proven by a fixture or the live site. Each entry has a status; do not treat an
`verify` entry as settled.

| ID | Topic | Assumption | Status | Where |
|---|---|---|---|---|
| T-1 | Bonus base | Tag bonuses are computed over the **lineup items** (≤ `slots`), not over FUT.GG's larger on-page pool. The decisive evidence is **position sums vs slots** on the FUT.GG page, not tag counts: the page lists *more positions than the set has slots* — currently **Málaga (23 positions for 15 slots)** and **TOTW (32 for 20)**; the PL page was **35 for 30** in an older snapshot, but the **current PL page shows midfield+attack = 15+15 = 30 at 30 slots**, so 35/30 may only be cited as an *older, dated* snapshot (see T-5). The bonus numbers move with those extra positions. "Only the ten biggest tags pay" **without an item count** is *not by itself* evidence of a larger pool — it is the position-sum/slot mismatch that shows FUT.GG bonuses over a larger pool than the app's lineup. The app must not blindly align with visible FUT.GG figures. | `verify` | README §"Bonus base (T-1)"; UI label "Bonus over lineup items" |
| T-2 | Slots cascade | When a set page states no slot count, slots are taken from the body text, then an index oracle (`{totw: 20}`), then default 15; recorded via `slotsEstimated` / `slotsSource`. | `verify` | `server.py` `parse_futgg`; `tests/test_parser.py::TestSlotsEligibility` |
| T-3 | Score→Level | EA publishes no complete score-to-Gallery-Level table, so the app optimizes Gallery Score and takes a target score as input. | `accepted` | README §"Important limitation" |
| T-4 | Reward = tokens | A grade reward counts as tokens only when a `gallery-token` image is present; otherwise reward 0 + `rewardText` (H6). | `verify` | `tests/test_parser.py::TestGradeTable` |
| T-5 | Dynamic breakdowns | FUT.GG tag breakdowns (item counts, %, bonus numbers) move with card scores. They are **dated snapshots**, never timeless product values. Only the tag *model* (per-tag floor, top-10 cut) and the property assertions are stable. | `accepted` | `tests/test_score.py::TestBonusUnitBands.test_pl_same_league_snapshot_2026_10_04` |
| T-6 | Inline script parse | Fixed a **pre-existing** bug: the Export button had `id="export"` and the wiring used `export.onclick`, so the whole inline script threw `SyntaxError: Unexpected token 'export'` in Chrome/Edge and never executed. Renamed to `exportBtn`. Guarded by a classic-script parse test. | `fixed` | `tests/test_form_fields.py::TestAppScriptParse` |
| T-7 | TAG-table oracle | `test_all_tags.py` reads expected percentages from the engine's own `TAG` table, so it cannot detect a wrong value *inside* it. Added an **independent, dated, offline** FUT.GG fixture (`tests/fixtures/futgg/bonus_tags.html`, fetched 2026-10-04) + `tests/test_tag_table.py`, comparing the engine table tier-by-tier (verified to fail on a deliberately corrupted value). The `countTopTags=10` default and the `Infinity` (=all) variant are tested too. | `fixed` | `tests/test_tag_table.py` |
| T-8 | R3 = Branch & Bound | The first P1 submission shipped Greedy-seed → budget-cap → 2-opt and only claimed B&B. R3 now **is** B&B: `branchAndBound` is `planSet`'s primary search (greedy is the seed only), with an admissible **monotone** upper bound (`setUpperBound`), a hard coin-budget check, seed-feasibility validation and a node cap. `planSet` reports `optimality: 'proved' \| 'node_limit'` so a plan is never silently presented as optimal when the node cap was hit. Proven by brute force **under a binding coin budget**, by a two-set portfolio test where a shared card's cost counts once (`coins − reserve`), and by a 25-candidate / ≤4-purchase brute force across **all four objectives** (`tokens`, `score`, `balanced`, `eff`). The **global portfolio** path likewise runs a real B&B over the shared card set S (see T-9/T-14). | `fixed` | `tests/test_plan.py::TestPlanOptimality`, `::TestPortfolioTwoSets`, `::TestSmallBruteForceAllObjectives`, `::TestPlanSetOptimalityReported` |
| T-9 | Portfolio cost model | Multi-set plans charge a shared card's **coin loss once** over the union of chosen cards; per-set score is the lineup-capped score. The reserve is withheld from the budget (`budget = coins − reserve`). `portfolioPlan` is **exhaustive (proven optimal)** for candidate universes ≤ `EXACT_PF_LIMIT` (20 cards); **beyond 20 it runs the global Branch & Bound over the shared card set S** with a greedy seed + budget-respecting 2-opt, and reports `optimality: 'proved' \| 'node_limit'` honestly (never "proven" when the node cap tripped, never a bare Greedy fallback). Proven against the exhaustive `portfolioBrute` on universes **> 20** (21/22/23/24 cards) for all four objectives, with shared cards and `coins − reserve`, and a `node_limit` case via `maxNodes`. | `fixed` | `tests/test_plan.py::TestPortfolioTwoSets`, `::TestTagSynergySharedCardBruteForce`, `::TestPortfolioOptimalityReported`, `::TestGlobalBbPathVsBruteForce` |
| T-10 | evalSet memo key | Bug found while wiring B&B: the memo key was `setId\|slots\|sorted(ids)` and ignored the **pool**, so the same id-set evaluated over different pools (`pool` vs `pool ∪ candidates ∪ units`) returned a stale value. Fixed: the key now includes the **resolved items** (identity + tag-relevant fields), so collisions are impossible. Regression test asserts both orderings. | `fixed` | `tests/test_plan.py::TestEvalSet.test_memo_key_includes_resolved_pool` |
| T-11 | B&B upper bound soundness | The first amended P1 used `evalSet()` over all remaining candidates as the B&B bound. `lineup()` is a **heuristic** selector and **NOT monotone** in the pool (proven: `lineup(P)=1723` but `lineup(P\{p6})=1888`), so that bound was **unsound** and could prune the true optimum. Replaced by `setUpperBound` = `Σ(≤slots largest base scores) + score(pool,{countTopTags:Infinity}).bonus`; both terms are provably monotone and dominate any realised subset. Guarded by admissibility + monotonicity tests. | `fixed` | `tests/test_plan.py::TestSetUpperBound` |
| T-12 | 2-opt refinement corrupted the B&B optimum | The first amended P1's `improve2opt` evaluated lineups over an eval-universe that omitted the candidates **and** an id-set that omitted the owned pool. Candidates were therefore invisible to `lineup()` and owned cards were dropped, so the refinement could replace a correct B&B optimum with a strictly worse set (reproduced for `balanced` and `eff`). Fixed: universe = `owned ∪ cands ∪ sel`, id-set = `owned ∪ list`, and an over-budget edit is rejected. The 25-candidate brute force now matches for all four objectives. | `fixed` | `tests/test_plan.py::TestSmallBruteForceAllObjectives` |
| T-13 | Bound precondition: non-negative scores | `setUpperBound`'s base term (`Σ of the ≤slots largest base scores`) is monotone **and** an upper bound **only if scores are non-negative**. With negative inputs it is neither: measured 3158/12000 monotonicity violations and 1563/2000 admissibility violations (e.g. bound 154 < realised 177). The engine now **enforces the precondition** by sanitizing every score through `sanScore` (NaN / missing / `Infinity` / negative → 0) at every read site (`bonus`, `score`, `lineup`, `poolFor`, `candidatesFor`, `_itemSig`, `setUpperBound`, `portfolioWorld`). Re-verified: 0 admissibility violations with adversarial negative/NaN pools. | `fixed` | `tests/test_plan.py::TestSetUpperBoundNegativeScores` |
| T-14 | Global portfolio must not silently degrade to Greedy | The second amended P1 only searched exactly up to `EXACT_PF_LIMIT` (20) candidates and fell back to **Greedy** beyond that — so a larger universe could present a greedy plan without proof. R3 requires the search over the **global card set S** with B&B then 2-opt. Fixed: beyond 20 candidates `portfolioPlan` runs `portfolioGreedySeed` → `portfolioBranchAndBound` (**global, S-indexed, `maxNodes`-capped**) → budget-respecting `portfolioImprove2opt`, and reports `optimality: 'proved'` (B&B exhausted) or `'node_limit'` ("best found") with `proven=false` when truncated. `portfolioBrute` was rewritten to enumerate size-≤`maxBundle` combinations (not raw bitmasks) so the reference is exhaustive past 20. Proven on universes 21–24 across all objectives + a forced `node_limit` via `maxNodes:1`. | `fixed` | `tests/test_plan.py::TestGlobalBbPathVsBruteForce`, `::TestPortfolioOptimalityReported.test_large_universe_*` |

## How to close a `verify` item

1. Re-fetch the relevant live page (or obtain an official statement).
2. Add or update a parse fixture under `tests/fixtures/futgg/`.
3. Add/refresh a parser test **and** (where the claim is about engine behavior) an
   engine assertion in `tests/`.
4. Flip the status here and record the evidence in `VERIFICATION.md`.
